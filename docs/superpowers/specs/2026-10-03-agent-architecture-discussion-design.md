## 1. Цель, как её поставил владелец

**Максимально функциональная агентная и многоагентная система.** Не только «найти и сделать в
интернете», но и **на телефоне — настройка окружений**: «как в Linux — открываешь второе окно со вторым
рабочим пространством».

Это не новая цель, а уже записанная: `docs/improvements-ru.md`, Часть 2, B и B.1 («настрой мне
лабораторию по химии»; окружение — именованный набор; **поверхность формирует агент** из палитры
`core/ui`, «агент выбирает, система размещает»), и манифест §14–18 («окружение — единица
делегирования», «выход — это компенсация», «личность — данные, а не веса»). Новое в 2026-10-03 —
**приоритет**: владелец назвал это целью разработки, тогда как спека A4′ §11 ставит окружения **после
A6**. Это расхождение — §13, пункт 4.

**Фишка продукта, по формулировке владельца:** «создай систему, какая тебе нравится» — пользователь
говорит, что хочет видеть, агент собирает окружение (§7, §7.1).

Владелец также уточнил: **SM-A325F — экспериментальный стенд, а не потолок продукта**; возможности
новее Android 13 (например, Android 16) проверяются на эмуляторе (образ Pixel 10).

## 2. Замеры этой сессии

### 2.1 OpenRouter — кто понимает `response_format: json_schema`

Провайдер владельца — **OpenRouter, модель любая** («я беру любую модель с этого сайта»). Замер — один
`GET https://openrouter.ai/api/v1/models` (публичный, без ключа), 2026-10-03; сырой JSON лежит в
scratchpad сессии и **не коммитится** — он дрейфует, ценность имеет только дата и метод.

| | моделей |
|---|---|
| всего | **466** |
| `structured_outputs` (то есть `json_schema`) | **380** (82 %) |
| `response_format` без `structured_outputs` (только `json_object`) | 36 |
| ни того, ни другого | **50** |
| без `structured_outputs` всего (36 + 50) | **86** |
| `structured_outputs` объявлен, `response_format` — нет | 18 |
| `tools` (нативный tool calling) | 398 |
| `openai/*` | 102 из 102 со `structured_outputs` |
| бесплатные `:free` | 5 из 17 |

**Флаг на модели — объединение по провайдерам, а не гарантия.** Тот же день, эндпоинт
`/api/v1/models/<id>/endpoints`:

| модель | провайдеров со схемой |
|---|---|
| `meta-llama/llama-4-maverick` | 4 из 4 |
| `meta-llama/llama-4-scout` | 2 из 3 |
| `meta-llama/llama-3.3-70b-instruct` | 7 из 11 |
| `meta-llama/llama-3.1-8b-instruct` | **1 из 5** (только CoreWeave) |

**Документация OpenRouter противоречит сама себе** о неподдерживаемом параметре: страница маршрутизации
— «providers … will ignore unknown parameters» (если не задан `require_parameters: true`); страница
structured outputs — «the request will fail with an error indicating lack of support». Без ключа
владельца не разрешимо. **Оба поведения закрываются безопасно** (проза → строгий парсер → `NoPlan`;
не-2xx → `NoPlan`), и это решает объём: безопасность моста держит валидатор, не транспорт.

### 2.2 AppFunctions — кто может их вызывать

Официальная документация (2026-10-03): вызывающему нужен `EXECUTE_APP_FUNCTIONS`; функция
**экспериментальная** — «only a limited number of apps and system agents can access the entire
pipeline»; доступна на Android 16+; для проверки есть `adb shell cmd app_function …`. Вторичные
источники описывают разрешение как выдаваемое привилегированным/одобренным агентам.

**Вывод:** обычная установка Sidr не вызовет чужие AppFunctions **даже на Pixel 10**. Обход для
разработки на эмуляторе (root-образ, установка как priv-app) **не проверен**. AppFunctions — будущий
источник инструментов с внешним условием (допуск Google), а не основание архитектуры сегодня;
архитектура обязана принять его как ещё один источник, когда он откроется.

### 2.3 Сверено в дереве

- `LlmCommandPlanner`: `DEFAULT_TIMEOUT_MS = 2_000`, `DEFAULT_MAX_OUTPUT_TOKENS = 256`, парсинг
  «от первой `{` до последней `}`»;
- `RouteCommandUseCase`: модель — шаг 7, ниже `localOnlyMode` (3), провайдера (5), сети (6);
  `CompositePlanner` работает на шаге **2b**, выше `localOnlyMode`;
- из семи `ActionIds` инструментами спроецированы только `launch_app` и `play_store_search`;
  `web_search`, `open_url`, `open_assistant`, `show_apps`, `open_settings` — нет;
- `ShortcutToolSource`: каждый ярлык — `SAFE` / `EXTERNAL` / `TRANSIENT`
  (`ShortcutToolSource.kt:71-73`): согласия на ярлыке не бывает, только провенанс;
- `RuntimeBudget.Default = (maxSteps = 8, maxConsecutiveFailures = 2)`; исчерпание шагов кончает
  план `Blocked` (`AgentExecutor.kt:108`);
- `ToolArgumentSorts` — три строки (`uninstall_app`, `open_app_info`, `set_app_alias`), сорт один —
  «приложение».

## 3. Развилка F3-1 — как требовать структурированный ответ

**Что даёт JSON-схема.** Без неё форма ответа держится на просьбе в промпте; со схемой
(`strict: true`) провайдер на каждом шаге генерации запрещает токены, нарушающие форму, — проза, чужое
поле, id не из списка становятся невыводимыми. **Это рычаг надёжности, не безопасности:** схема не
пропускает ничего, что не отклонил бы детерминированный валидатор; смысл (тот ли инструмент) она не
гарантирует; от обрыва по лимиту токенов не спасает. Есть работы, где жёсткое ограничение формата
ухудшало рассуждение (Tam et al., 2024, «Let Me Speak Freely?»), — оспорено, на нашей задаче не
проверено.

| | вариант | цена |
|---|---|---|
| a | всегда отправлять `json_schema` | на ~86 моделях мост мёртв или держится на промпте — неизвестно, что из двух |
| b | не отправлять: схема в промпте + строгий валидатор | на слабых моделях больше честных `NoPlan` |
| **b′** | **форма ответа строится так, будто схема есть; отправляется только промпт** | генератор схемы + тест согласия с промптом + один повтор |
| c | отправлять там, где модель умеет | определение возможностей (API OpenRouter, не общий) или повтор после 4xx |

**b′ подробно:** форма ответа strict-совместима (все поля обязательны, `null` вместо «необязательно»,
лишние запрещены); JSON-схема генерируется в `:domain` **из того же реестра, что текст промпта**, и
покрыта тем же гвардом egress; валидатор + **один** повтор с текстом ошибки валидатора (повтор
безопасен: до валидации не исполняется ничего); отправка схемы провайдеру — флаг. Транспорт —
деталь адаптера `:data:ai-cloud`: промпт / `response_format` / форсированный `submit_plan` через канал
`tools`.

**Рекомендация: `b′ + замер`.** Замер — задача внутри 3a, **не** до плана (объём не решает, выбирает
только транспорт по умолчанию): харнесс по образцу `SelectionDeclineMeasurement` (`B15`) с
git-игнорируемыми входами; корпус владельца из 25 формулировок × 2–4 его модели × три транспорта;
считается доля распарсенных, доля прошедших валидатор, доля правильных (судит владелец), медианная
задержка, и **съедают ли скрытые рассуждения лимит токенов**. Ключ — из переменной окружения, скрипт
запускает владелец.

## 4. Tool calling (ReAct) против «план целиком» — почему не меняем форму цикла

Tool calling: запрос несёт `tools` с JSON-схемами; модель отвечает текстом **или** `tool_calls`; клиент
исполняет, дописывает результат (`role: "tool"`), спрашивает снова — пока модель не ответит текстом.

| | «план целиком» (Sidr) | tool calling циклом (ReAct) |
|---|---|---|
| обращений к модели на задачу | 1 (+ перепланирование) | N+1 |
| что уходит наружу | команда + статическая схема | **+ результат каждого шага** |
| согласие видит весь план | да (`DOC-HMA-3` по построению) | нет — необратимость узнаётся по ходу |
| адаптация к результатам | только предвиденная (связки, предусловия) | полная |
| ответ словами | строить | из коробки (ADR 4/4) |
| кэш / офлайн-повтор (фаза 4) | да | нет — траектория не шаблон |
| смерть процесса | план + курсор | весь разговор на диске, миграция Room |

**Индустрия 2026 года** ([futureagi](https://futureagi.com/blog/agent-architecture-patterns-2026/),
[dev.to](https://dev.to/gabrielanhaia/react-vs-plan-and-execute-picking-an-agent-loop-in-2026-gnk),
[atlan](https://atlan.com/know/ai-agent/react-vs-plan-and-execute-agent-architecture/)): чистых форм в
продакшене мало; частые гибриды — граф/супервизор снаружи с ReAct на листьях, и «план целиком» с
ReAct-исполнением шагов и перепланированием, когда план устарел. Для нетривиальных задач «план
целиком» рекомендуется **по безопасности**: [arXiv 2509.08646](https://arxiv.org/abs/2509.08646) —
устойчивость к косвенным инъекциям «by establishing control-flow integrity», плюс минимальные права,
инструменты в пределах задачи, песочница, человек в контуре.

**Решение: форму цикла не менять.** Tool calling циклом — альтернатива с **триггером**: первая задача,
которую нельзя выразить планом заранее, потому что следующий шаг зависит от **прочитанного
содержимого**; это ADR, потому что главная цена — egress, а не код. **Находка:** перепланирование
после отказа (`priorObservations`, фаза 3b) — **уже маленький ReAct**: наблюдения прошлой попытки
уходят модели. Сегодня это закрытый словарь `ObservedFact`, поэтому ни утечки, ни инъекции через него
нет — и это надо держать гвардом (§6, механизм 4).

## 5. Бюджеты — три разных, и только один должен быть строгим

Бюджет **роутера** (2000 мс, 256 токенов) создан под один быстрый выбор из семи действий. Перенесённый
на агента, он бы: **всегда** давал `NoPlan` рассуждающим моделям (отвечают за 5–60 с; ещё **не
проверено**, входят ли скрытые рассуждения в лимит токенов — пункт замера F3-1); не вмещал бы
многошаговый план (≈ 500–1500 токенов на 5–10 шагов — оценка); не вмещал бы содержимое. Строка `B5`
это предвидела.

| бюджет | что ограничивает | каким быть |
|---|---|---|
| на **размышление** (планировщик) | сколько ждать плана | щедрым и по модели: видимое «думаю…» с отменой; жёсткий потолок (порядка 30–60 с — гипотеза, цифры даёт замер) — гарантия конца, не суждение о качестве. **Новое состояние поверхности**: сегодня планирование идёт до старта сессии и не показывает ничего |
| на **содержимое** (шаг «составить текст») | длину текста | большим и потоковым, отменяемым в любой момент |
| на **действия** (`RuntimeBudget`) | сколько агент делает в мире без человека | **строгим** — граница из Hard rules («loop bounds»), отличие агента от фонового цикла (change-control §5) |

**Предложение (изменение поведения, не текущее):** исчерпание лимита шагов — не `Blocked`, а вопрос
«план длиннее обычного — продолжить ещё на N шагов?». Граница остаётся, решает человек.

**Длинный текст не живёт внутри ответа-плана** (найдено на примере «составь маршрут и сохрани в PDF»):
«составить текст» — **отдельный шаг** программы, исполняемый существующим потоковым движком ассистента
(`GenerativeAiEngine`, SSE). План остаётся коротким и надёжным, текст печатается на глазах. Порты не
объединяются (Hard rules; change-control §5): шаг вызывает движок как воркер, а не сливает его с
`Planner`. **Цена, названная сразу:** это новый путь наружу **внутри слоя инструментов** — ему нужен
тот же гвард egress (§14).

## 6. Ставка: «слепой планировщик, зрячее устройство»

**Модель никогда не видит мир пользователя** — ни списка приложений, ни названий ярлыков, ни
содержимого. Она видит команду и **наш** словарь способностей и пишет программу нашими словами.
Привязку к миру делает устройство, детерминированно.

```
 команда
   │
   ▼
 [ЗАМЫСЕЛ]     модель: команда + НАШ словарь → программа на способностях;
   │           в слотах — упоминания («телега», «10 минут») и подсказки поиска
   ▼
 [ПРИВЯЗКА]    устройство: упоминание → сущность (резолвер сорта);
   │           способность → конкретный инструмент (авторский / ярлык / позже AppFunction, MCP);
   │           неоднозначно или найдено по подсказке → вопрос, никогда не догадка
   ▼
 [ВОРОТА]      анализ ВСЕЙ программы: риск, необратимость, эффекты, потоки меток →
   │           одна карточка (для меняющих состояние — разница «было → станет», §7)
   ▼
 [ИСПОЛНЕНИЕ]  AgentExecutor: одна точка вызова, бюджеты, трасса, откат
   │
   └── отказ / устаревание → в модель: цель + ТИПИЗИРОВАННЫЕ наблюдения, не текст мира
```

**Механизм 1 — упоминания вместо значений.** В слот модель пишет слова пользователя (`app: "телега"`),
а не `com.whatsapp`. Валидатор детерминированно проверяет, что упоминание **выводимо из команды**
(дословный фрагмент — базовый случай); сущность находит резолвер сорта на устройстве
(`AppTargetResolver` — «никогда не угадывает»). Модель не может подсунуть сущность, которой
пользователь не называл. **Пределы (названы в ходе самопроверки):** морфология — не только турецкая
(`telegramı`), но и русская («телегу», «телеге»): резолвер обязан понимать формы слова; ссылка на
прошлую реплику («и его удали») — фрагмент лежит в **прошлой** реплике, значит контекст разговора
участвует в проверке; неявные аргументы («как обычно») — из памяти на устройстве; опечатки —
резолвер, который не угадывает, на них откажет. **Прецедент есть** (§11): «literal binding» в SIEVE,
«grounding firewall» saidso.

**Механизм 2 — способности вместо инструментов, и «модель придумывает, что искать, — телефон ищет у
себя».** Модель выбирает из нашего словаря: авторские инструменты (17 после исключения
`launcher_memory`) плюс общая способность вида `run_app_action(app, action)` со **словами-подсказками**
из собственных знаний модели («Send, Transfer, Перевести, Отправить») — не из телефона. Устройство
сверяет подсказки со **своими** названиями ярлыков. Так динамический ярус достижим моделью, которая
его не видит, — и растворяется конфликт спеки §7.10 (манифест §16 против `OutboundContextPolicy`).
**Поправка самопроверки:** ярлыки `SAFE` (§2.3), ворота на них **не спрашивают**, а подсказки ищут
свободнее `ToolSelector` — поэтому ярлык, найденный **по подсказке**, а не по словам пользователя,
всегда сначала спрашивает «Открыть "Cake Wallet: Send"?», пока выбор не выучен (память выученных
резолюций, порог сегодня — серия ≥ 3). Это **уточнение понимания** (`DOC-NYH-1`), а не новая ось
согласия — `DOC-ADL-1` не страдает.

**Механизм 3 — программа с ветками; согласие — по анализу всей программы.** Ограниченный язык:
последовательность, связки F6, «если наблюдено …», перебор с пределом, «спросить», «сказать»
(«сказать» — ADR 4/4: ответ словами есть программа без действий; лечит находку (d) приёмки A1″).
Без неограниченных циклов анализ полный: до первого действия известны риск и необратимость **каждой
ветки**; `DOC-HMA-3` — по построению. План A0 «запустить → магазин» — такая программа, написанная
рукой. **Противоречит спеке §11** («HTN и синтез — ниже моста») — §13.

**Механизм 4 — обратный канал к модели — только закрытый словарь.** При перепланировании уходят цель и
`ObservedFact`. Долг A0.5 «целый класс реальности несказуем» становится **свойством безопасности**:
каждое новое наблюдение — явное решение о приватности. Держится гвардом: ни одной сторонней строки в
наблюдениях, уходящих модели.

**Механизм 5 — метки происхождения на каждом значении.** «сказал принципал» (сегодня принципал
всегда пользователь; метка хранит, **кто** — манифест §19, машинный пользователь потом не потребует
переименования по всему ядру) / «наше» /
«приватное устройства» / «стороннее» / «сгенерировано моделью». У каждого стока — политика: наружу —
только «сказал пользователь» + «наше»; в аргумент необратимого шага — только привязанная сущность,
показанная на карточке; сгенерированный моделью текст в долговременный сток — только показанный на
карточке дословно. `OutboundContextPolicy` растёт из «категорий контекста» в «метки на значениях»;
гвард egress проверяет **нагрузку**, а не инвентарь (шестой барьер §7.1 спеки — системно). Чтение
содержимого (уведомления, страницы) — только локальной моделью, в типизированные значения с меткой
«стороннее»; до `B16` таких задач нет — честный предел.

**Механизм 6 — квитанция исходящего.** Каждый запрос наружу оставляет пользователю видимую запись: что
ушло, кому, зачем — дословно, без ключа; возможно — и стоимость (§14). Спека §7.3 назвала политику
«механизмом честности»; квитанция делает честность видимой пользователю, а не только тестам.
**Прецедент есть:** Apple Intelligence Report (журнал запросов к Private Cloud Compute) — §11.
Хранение квитанций — сырой текст команды на диске: эфемерно или под управлением пользователя (§14).

**Следствия.** (а) **Программы становятся рутинами пользователя** (фаза 4): кэшируется непривязанная
программа и привязывается заново на каждом запуске (спека §8.2 уже требует); видима, правима, удаляема
(`DOC-AML-5`); происхождение — по `DOC-ILM-5`; со временем больше команд исполняется без модели.
(б) **Место вывода выбирает метка** (когда будет `B16`): запрос из «сказал пользователь» + «наше»
может идти в облако, остальное — локально или детерминированно. Модель выбирает пользователь, **где**
ей работать — политика.

**Что ставка стоит в функциональности — честно.** На задачах (оценки, не замер):

| задача | спека как есть (в) | слепой + подсказки (а) | (а) + «окно»: модель видит приложения и ярлыки по выбору пользователя |
|---|---|---|---|
| «маршрут по музеям Парижа» | ✗ гуглит | ✓ | ✓ |
| «удали инстаграм» | ✓ | ✓ | ✓ |
| «переведи маме 100 долларов» (ярлык по смыслу) | ✗ | ✓ в первый раз — один вопрос | ✓ сразу, если модель угадала |
| «сколько у меня сегодня встреч» | ✗ | ✓ считает телефон, модель календаря не видит | ✓ так же |
| «что важного в уведомлениях» | ✗ | ✗ до локальной модели | ✗ |
| вес каждой команды | малый | малый | +~5 тыс. токенов на ярлыки (по замеру `B3`) |
| инъекция через сторонний текст | нет | нет | есть (рискованное всё равно стопорит согласие) |
| «Sidr не отправляет ничего о вас» | правда | правда | правда, пока окно закрыто |

**Окно экономит ровно один вопрос на новую формулировку** и платит весом каждой команды, вектором
инъекций и правдой обещания. В архитектуре с метками окно — одна запись политики плюс гвард, добавить
его позже дёшево. Рекомендация — **(а)**, окно записать с триггером («приёмка показала, что уточнения
раздражают»).

**Улучшение из литературы, которого у нас нет** (PAAC, май 2026, §11): облачный агент рассуждает над
**типизированными заглушками** вместо чувствительных значений — даже внутри самой команды («напиши
Ахмеду…» → «напиши [PERSON_1]…»), а устройство распознаёт чувствительные фрагменты. У нас команда
уходит дословно (`USER_COMMAND` разрешён — пользователь сам напечатал). Кандидат на после `B16`
(распознавание фрагментов требует локальной модели).

## 7. Новое: окружение как ЖЕЛАЕМОЕ СОСТОЯНИЕ, а не скрипт

> Идея этой записки; с владельцем ещё не обсуждалась. Прецедента в телефонах поиском 2026-10-03
> **не найдено** (поиск неглубокий, §11).

Аналогия владельца — Linux; точнее всего ложится **NixOS**: система описана декларацией, переключение
атомарно, откат — к предыдущему поколению.

- **Окружение — декларация**, а не последовательность шагов: «поверхность: [элементы]; звук: тихо;
  не беспокоить: до 23:00, избранные пробиваются; обои: X; будильник: 7:00; на виду: [карты,
  переводчик, билеты]; грант: …; выход: по времени / по месту / вручную».
- **Активация — сверка** (детерминированная): прочитать текущее значение каждой ручки → вычислить
  разницу → показать её **как согласие** («будет изменено: 5; без изменений: 2; потребует вашего
  касания: Wi-Fi») → применить → **сохранить прежнее поколение** (снимок ручек, которые тронуты).
- **Выход — сверка обратно к прежнему поколению.** Откат — не цепочка обратных шагов, а восстановление
  снимка. Обобщает компенсацию фазы 2 правилом **«прочитай перед записью»**: инструмент, меняющий
  состояние, сообщает прежнее значение выходом — так уже делают `set_app_alias` / `forget_app_alias`
  (фаза 2, T5).
- **Дрейф.** Пока окружение активно, пользователь включил звук руками → окружение замечает и спрашивает
  «оставить как сейчас или вернуть по окружению?»; **ручное изменение пользователя побеждает по
  умолчанию**.
- **Роль модели** — один раз написать декларацию по фразе («настрой мне лабораторию по химии») нашим
  словарём, вслепую (§6); устройство привязывает; пользователь правит; сохраняется данными (манифест
  §18) и дальше воспроизводится **без модели и офлайн**.

**Почему лучше императивного плана:** идемпотентно (применить дважды = то же); выход точен **для
каждой ручки, текущее значение которой Sidr может прочитать** (снимок) — оговорка §7.1; разница прячет
пустые операции и показывает настоящие изменения (`DOC-NYH-2`, `DOC-MZN-2`);
переносимо — декларация переезжает на новый телефон, привязка делается заново (improvements A + B).
**Чем отличается от существующего:** Samsung Modes & Routines и iOS Focus — автоматизация «при входе
сделай X», без согласия по разнице, без поколений, не собираются агентом из языка.

**Применимость на Android без root** (известные ограничения платформы; на стенде не мерено):

| ручка | статус |
|---|---|
| своя домашняя поверхность (раскладка, скрытие, ярлыки, виджеты) | меняем сами — это наше (`LauncherStateToolSource` из improvements B) |
| обои | меняем сами — `SET_WALLPAPER` **уже объявлен и не используется** (спека §7.4) |
| будильники, таймеры | меняем сами (есть) |
| «не беспокоить», режим звонка | после одного разрешения пользователя (доступ к политике уведомлений) |
| яркость | после одного разрешения («изменение системных настроек») |
| Wi-Fi, мобильные данные, отчасти Bluetooth | **только открыть экран** — с Android 10 приложения их не переключают; класс одиннадцати навигаторов A1″ |
| чужие AppFunctions | закрыто (§2.2) |
| автоматизация чужого интерфейса | закрыто сознательно: accessibility-сервисов у Sidr ноль (спека §7.4) |

### 7.1 «Создай систему, какая тебе нравится» — визуальный слой (владелец, 2026-10-03)

**Формулировка владельца — фишка продукта:** «создай систему, какая тебе нравится». Пример (только
пример): «собери мне особый дизайн "аквариум"» — агент перестраивает систему отдельным окружением, с
плавающими рыбами на рабочем столе, и так далее. Пользователь говорит, **что хочет видеть**, а не как
это сделать, — то есть именно декларация (§7).

**Чем это отличается от существующего** (неглубокий поиск, по памяти о продуктах): темы Samsung и Good
Lock — только внешний вид, вручную, на привилегиях производителя; Modes & Routines и iOS Focus —
поведение по правилам, вручную; сгенерированные обои Android 14 — одни обои. **Язык → целое окружение
(вид + поведение + способности) как данные, с согласием по разнице и точным выходом** — прецедента не
найдено. Это и есть претензия на оригинальность продукта, не только архитектуры.

**Слои — что Sidr может, измерено документацией платформы, не стендом:**

| слой | что можно | оговорка |
|---|---|---|
| **своя поверхность** (Compose-дом Sidr) | всё: тема, цвета, сетка, иконки (Sidr рисует их сам), виджеты, **анимированная сцена** | наш процесс — точный снимок и точный выход; цена — батарея и кадры (пауза, когда дом не виден; reduce-motion → статично) |
| **системные обои** | **записать** — да (`SET_WALLPAPER` уже объявлен); живые обои — Sidr может нести свой `WallpaperService`, включение — **одно касание** в системном экране | **прочитать текущие — нет** на Android 14+: `getDrawable()` отдаёт обои по умолчанию без `READ_WALLPAPER_INTERNAL` (системное) или `MANAGE_EXTERNAL_STORAGE` («доступ ко всем файлам», ограничено политикой Play) — [коммит AOSP](https://android.googlesource.com/platform/frameworks/base/+/b55648924c6d). Значит, **точно вернуть обои, которые ставил не Sidr, нельзя** |
| **цвета системы** (Material You, Android 12+) | меняются **через обои**: системная палитра выводится из них — так «аквариумный» синий доходит и до приложений, использующих динамический цвет | напрямую задать акцент системы стороннее приложение не может |
| звуки уведомлений и звонка | после разрешения «изменение системных настроек» | — |
| строка состояния, быстрые настройки, шрифты, вид чужих приложений, экран блокировки кроме обоев | **закрыто** без root / привилегий производителя | — |

**Отсюда решение формы:** сцена окружения по умолчанию живёт **в собственной поверхности Sidr**, а не в
системных обоях, — там выход точен. Системные обои — **необязательная** ручка («перекрасить и
приложения, и экран блокировки»), и её выход честно назван на карточке: «вернуть прежние обои Sidr не
может — выберите их в системе». Альтернатива — один раз попросить пользователя задать «базовые обои»
**через Sidr**, тогда источник есть у Sidr и выход точен.

**Откуда берётся «особый дизайн» — три источника, по нарастанию риска:**

1. **Палитра сцен в самом Sidr** — параметрические сцены («аквариум: рыб 7, медленно, пузыри»; «лес»;
   «дождь»; «космос»): детерминированно, офлайн, малый вес. Модель выбирает сцену и параметры, система
   рисует — «агент выбирает, система размещает» (improvements B.1). **Начинать отсюда.**
2. **Генерация изображений моделью** — по-настоящему «особый»: наружу уходят только слова пользователя;
   цена — деньги, задержка, разброс качества; всё сгенерированное помечено (`DOC-ILM-5`).
3. **Окружения как данные, которыми можно делиться** — декларация, а не код, проверяется закрытой
   палитрой, поэтому чужое окружение **не может исполнить произвольный код** (improvements Часть 3 C:
   «конфигурации, не код»; аналог flakes в NixOS). Импорт — через ту же карточку разницы.

**Как это примиряется с нейтральной эстетикой (improvements B.1).** Два слоя, как обои и окна в Linux:
**сцена** (фон, атмосфера) — где живёт характер; **функциональный слой** (ярлыки, виджеты, заметки) —
остаётся систематическим, размещается правилами дизайн-системы, токены цвета подстраиваются под сцену.
Аргумент B.1 («декорированный язык ломается на непредвиденной композиции») относится к функциональному
слою и в нём сохраняется.

**Доктрина визуального слоя — вопросы владельцу, не решения агента:**
- `DOC-SKN-1` — «idle animation budget = 0»: плавающие рыбы — это idle-анимация. Правило писалось для
  собственной поверхности Sidr по умолчанию; распространяется ли оно на окружение, **заказанное
  пользователем**, — решение доктрины (change-control: изменение правила — ADR);
- `DOC-SKN-3` — «sacred density»: ничто не конкурирует за внимание с сакральной строкой — сцена у
  сакральных элементов должна гаснуть, или окружение их скрывает, или правило запрещает сцену там;
- изображения живых существ в генерируемых сценах — если для доктрины Sidr это вопрос, решать
  владельцу (например, настройкой); техника от ответа не меняется.

**Цена, названная сразу.** Ценность пропорциональна **богатству палитры** — иначе это игрушка «обои и не
беспокоить» (риск, записанный в improvements B). Настоящая работа блока окружений — палитра сцен,
элементов и поведений; декларация, сверка и поколения — её каркас.

### 7.2 Окно полного доступа — идея владельца 2026-10-03, мнение агента

**Идея как поднята:** «особое секретное окно/окружение, которое открывает полностью все возможности для
пользователя — и агента, и человека — по строгому разрешению».

**Мнение агента: хорошая идея при одном условии — «полный доступ» означает максимум ДОСТИЖИМОГО, а не
минимум ГЕЙТОВ.** Манифест §13 уже делит «запрещено» на два вида: (1) «пока пользователь не разрешил» —
выдаётся законно, со скоупом, лимитом и отзывом; (2) целостность — не выдаётся никогда. Окно открывает
**весь первый вид разом, на время, по сильной аутентификации — и ничего из второго**. Это `sudo` из
аналогии с Linux: временное повышение по паролю, с меткой времени и журналом, — но даже root здесь
ходит через ядро (реестр, трасса).

**Почему это лучше альтернативы:** без окна мощность получают постоянными разрешениями, разбросанными
по системе и забытыми; окно **собирает риск в одно место — видимое, ограниченное по времени,
аутентифицированное**. И даёт законный дом всему, что слишком рискованно для режима по умолчанию: окну
D1 (модель видит приложения и ярлыки), агенту-исследователю с интернетом, внешним машинным принципалам
(манифест §19), долгим фоновым задачам (foreground service с уведомлением — `DOC-HMA-4`), большим
бюджетам, экспериментальным инструментам. Для исследовательского проекта на экспериментальном стенде —
«лаборатория», в которой проверяется граница возможного, не ослабляя продукт по умолчанию.

**Как может выглядеть:**

1. **Вход — только руками человека.** Ни один инструмент и ни один агент окно не открывает (инвариант,
   держится гвардом: в реестре нет инструмента, меняющего уровень повышения). Скрытый вход — как
   «Параметры разработчика» Android; команда «открой мастерскую» лишь **показывает** карточку входа →
   системная биометрия или код устройства (`BiometricPrompt`) → карточка разницы «что откроется / что
   остаётся всегда» → выбор срока (15 / 30 / 60 мин) → вход.
2. **Внутри — невозможно не заметить.** Цветная рамка поверхности Sidr + постоянное уведомление
   foreground service (его и так требует `DOC-HMA-4`) с таймером и «Выйти»; квитанции исходящего —
   вживую.
3. **Что открывается:** все инструменты, включая экспериментальные; модель видит приложения и ярлыки
   (окно D1, явное расширение egress, показанное на входе); исследователь с интернетом и многоагентность;
   внешние агенты — только пока окно открыто и только по поручению открывшего; специальные разрешения
   (не беспокоить, системные настройки, статистика использования) — запрашиваются один раз; большие
   бюджеты. **Под вопросом отдельным решением** — автоматизация чужого интерфейса через accessibility:
   это настоящее «всё» на Android и самое опасное (косвенные инъекции через экран — [arXiv
   2608.08939](https://arxiv.org/pdf/2608.08939)); плюс политика Google Play ограничивает такое
   использование accessibility.
4. **Что не открывается никогда** (манифест §13, второй вид): исполнение в обход реестра; пропуск
   валидации; пропуск allow-list исходящего (шире — да, без него — нет); «больше не спрашивай» на
   необратимом — необратимое спрашивает **каждый раз**; цикл без бюджета (бюджет больше — да, без него —
   нет); выключение или удаление трассы.
5. **Выход — автоматический:** по сроку, при блокировке экрана, вручную, при смерти процесса →
   восстановление поколения (§7), отзыв всех грантов → отчёт «за сессию: N действий, M запросов наружу,
   K необратимых — каждое с вашим подтверждением».
6. **Машинные принципалы** окно не открывают; внутри действуют только по поручению человека, который его
   открыл, и помечены в трассе своим именем.

**«Секретное» — предлагается «скрытое, но не тайное»:** спрятано от случайного касания, но
задокументировано и **никогда не невидимо, пока активно**. Тайный режим силы — ровно то, что ищут
мошенники («откройте вот это, я помогу удалённо»): карточка входа говорит об этом фактом, без
давления (`DOC-HYA-1`); удалённое открытие невозможно; срок ограничен.

**Риски, названные сразу:** социальная инженерия — биометрия, срок, запрет удалённого открытия;
привыкание (жить в окне постоянно) — потолок срока и повторная аутентификация для продления; часть
специальных разрешений Android выдаётся только вручную в настройках — один раз; accessibility — политика
Play.

**Доктрина:** `DOC-HMA-5` — окно и есть это правило в чистом виде; `DOC-HMA-4` — индикатор окна =
обязательное уведомление непрерывности; `DOC-AML-1` — расширение egress внутри окна — по ADR и с гвардом
**на каждый режим**; `DOC-ILM-3` — трасса не выключается; `DOC-ADL-1` — тот же риск, тот же гейт.

**Прецеденты** (по памяти, глубоко не искал): `sudo`; «Параметры разработчика» Android (скрытый вход);
Private Space Android 15 (скрытое аутентифицированное пространство — но для приватности, не для
повышения); Lockdown Mode iOS (обратное направление — меньше возможностей). Режимы кодовых агентов
«пропустить все подтверждения» — **противоположность**: они снимают гейты, окно Sidr расширяет
досягаемость и гейты оставляет.

На **ПК** (второй потребитель) окружения — буквально рабочие столы: «подготовь окружение для работы над
Sidr» = IDE + терминал + документы на втором рабочем столе, тот же движок. Вероятно, лучшая
демонстрация критерия 10.

## 8. Многоагентность — как разделение прав, а не «чаты, говорящие друг с другом»

> Основание в манифесте — §19 «Пользователь — не обязательно человек» и §20 «Устройство — любое»
> (добавлены по решению владельца 2026-10-03): первый вопрос ядра — «от чьего имени»; машина действует
> только по поручению человека и повысить себе права не может.

| агент | видит | может | модель |
|---|---|---|---|
| **исследователь** | интернет, страницы (сторонний текст) | ничего на телефоне | облачная — публичные страницы не о пользователе |
| **устройство** | приватное: приложения, календарь, состояние | настраивать телефон и окружения | детерминированно или локальная |
| **планировщик** | только команду и наш словарь | раздавать подзадачи, собирать | любая, слепая к миру |

Инъекция со страницы **не дотягивается** до инструментов телефона — у читающего их нет; выход
исследователя — значения с меткой «стороннее» (положить в заметку, показать — да; выбирать ими действия
— нет). Это идея CaMeL, поднятая с уровня модели на уровень агентов; **прецедент есть** — IsolateGPT
(изоляция сторонних приложений в LLM-системе по схеме hub-and-spoke) и CAMPHOR (иерархия агентов на
устройстве), §11. Попутно: параллельность и **разные модели под роли** (быстрая — план, сильная —
исследование, локальная — приватное).

**Пример — «подготовь телефон к поездке в Париж»:** исследователь — маршрут и часы работы музеев в
заметку или PDF (содержимое **курируемое**: с показанным источником, `DOC-ILM-5`); устройство —
окружение «Париж» по §7; грант «пока активна поездка, можно глушить звонки после 23:00»; выход —
восстановление поколения.

**Шов, который не закрывать уже в 3a:** шаг, исполняемый другим агентом, — это **инструмент, чья
реализация — сессия**. Ничего не строится; порт `Planner` и движок просто не закрываются на «один план
— одна сессия».

## 10. Пример насквозь — «составь маршрут по музеям Парижа и сохрани в PDF»

```
1. текст = составить_текст(«маршрут по музеям Парижа»)          ← модель, потоком; «сгенерировано»
2. файл  = сохранить_pdf(«Музеи Парижа», текст ← 1)              ← телефон (PdfDocument), без новых разрешений
3. открыть(файл ← 2)  или  поделиться(файл ← 2)                   ← связки F6 уже есть
```

Наружу уходит только фраза пользователя. Карточка до записи показывает весь текст с пометкой
«составлено моделью» и место сохранения. Созданный файл откатываем (удалить). **«В заметки» — иначе:**
универсального API записи в чужие заметки нет; текст передаётся через «Поделиться», заметки открываются
с текстом, пользователь жмёт «Сохранить» — исход за приложением (`HandedOff`, фаза 0), отката нет.
Без касания — только по собственному пути приложения (у Obsidian есть URI новой заметки) или через
AppFunctions (закрыто, §2.2). Чего не хватает: шаг «составить текст», инструменты «сохранить PDF/файл»
и «открыть/поделиться».

Поиск 2026-10-03, **неглубокий**; часть — по памяти, помечено.

| механизм записки | прецедент | вывод |
|---|---|---|

| квитанция исходящего | Apple Intelligence Report — *по памяти* | не ново |
| контроль информационных потоков для агентов | FIDES (Microsoft, 2025) — *по памяти* | не ново |
| **окружение как желаемое состояние: агент пишет декларацию из языка, активация — согласие по разнице, выход — поколение, дрейф** | NixOS / Home Manager (декларация + поколения, для ПК); Terraform `plan/apply`; Kubernetes-сверка; на телефонах — Modes & Routines, Focus (императивно) | **в такой комбинации для телефона прецедента не найдено** |
| **согласие человека по анализу ветвящейся программы целиком, до первого действия** | CaMeL и PAAC держат политику машиной, не показывают программу человеку | **прецедента не найдено** |

| вся комбинация в лаунчере-ОС под доктриной, на двух потребителях | — | вероятно ново; утверждать публично — только после настоящего обзора литературы |

**Вывод для «ищи оригинальное».** Каркас (§6) — сумма известных хороших идей, и это **достоинство**:
каждая проверена кем-то ещё. Оригинальность Sidr — в трёх местах выше, помеченных «прецедента не
найдено», и **главная из них — окружения как желаемое состояние (§7)**: она же ближе всего к цели,
названной владельцем (§1).

## 14. Что легко упустить — найдено самопроверкой 2026-10-03

- **Нерешённая развилка первого сообщения сессии:** семь `ActionIds` и инструменты — один каталог или
  два; судьба старого пути роутера (`PlanResult.RoutedAction` → `CommandOutcome.RoutedAction` →
  карточка). Два модельных пути = два пути наружу и два валидатора.
- **Хранение:** новая форма плана (ветки, метки) трогает схему Room 4 (миграция) и JSON-хранилище JVM
  без поля версии — известный долг A0.5 (4): старая сессия молча удалится как «порча».
- **Фон:** долгая многоагентная задача умрёт с процессом; foreground service — изменение модели
  исполнения (change-control §5, `DOC-HMA-4`, триггер `B6`).
- **Деньги:** при BYOK каждый вызов оплачивает пользователь; многоагентность умножает вызовы; бюджета в
  деньгах нет нигде — квитанция может показывать стоимость.
- **Новые пути наружу:** шаг «составить текст» — изнутри слоя инструментов; агент-исследователь,
  скачивающий страницы с телефона, — сетевой канал, который `OutboundContextPolicy` (политика запросов
  к модели) не покрывает.
- **Данные на диске:** рутины, квитанции, сгенерированный текст, контекст разговора — больше сырого
  текста; вопрос `secure_delete` (остаток A1′ №10) открыт.
- **Второй потребитель:** валидатор, проверка упоминаний, метки, генератор схемы — в `commonMain`;
  HTTP-транспорт сейчас в `:data:ai-cloud` (Android) — JVM нужен свой, иначе критерий 10 не выполнен.
- **Локализация:** каждая новая строка карточки — три локали в одном коммите; турецкие — на суд
  владельца.
- **Продолжение разговора** («добавь ещё Орсе»): нужен контекст прошлых реплик; разрешённые метки —
  да, привязанные сущности утечь туда не должны.

## 15. Предложение по фазе 3 — разрез 3a / 3b (предложен владельцем; содержимое сдвинуто обсуждением)

**3a — мост, первый срез целевой архитектуры:**
- описания инструментов **параллельным портом** (барьер 1) — в форме «наш словарь способностей» с
  пространствами имён («устройство», «лаунчер», «содержимое»), чтобы окружения легли потом без
  переделки;
- рендерер — **фильтр по уровню** (§7.6 спеки): авторские минус `launcher_memory` (`B13`, §7.5);
- форма ответа strict-совместимая, схема генерируется из реестра, строгий валидатор `ToolId` + **один
  повтор** (F3-1 = b′); замер транспорта — задачей внутри фазы;
- **упоминания с проверкой выводимости из команды** и привязка через **существующие** сорта
  (`ToolArgumentSorts` + `AppTargetResolver`);
- **минимум меток**: на каждом значении, уходящем в модель и приходящем от неё («сказал
  принципал» — с тем, кто он / «наше» / «сгенерировано моделью»);
- ADR egress + гвард **по настоящей нагрузке** с сентинелом из динамического яруса (§10 крит. 6);
- **свой бюджет** модельного планировщика (не 2000/256), видимое «думаю…» с отменой (`B5`, §5);
- модельный планировщик — **на шаге 7**, ниже гейтов 3/5/6 (`DOC-ADL-3`), его ответ становится
  `ExecutionPlan` и идёт через движок; развилка «семь `ActionIds` + роутер» (§14) решается здесь.

**3b — как предложил владелец:** полная сорт-система с ADR по `ArgType` (F6); перепланирование после
отказа + развилка «уходят ли наблюдения наружу» (гвард закрытого словаря, механизм 4); многошаговые
планы на Android; паритет JVM (свой транспорт); отложенные тесты фазы 2 (N2, T3 m3, T4 M2, T6 m5).
Плюс шаг «составить текст» (§5), если владелец оставит его в A4′.

**Вне A4′, пока спека не поправлена (§13):** ветки в программе, общая способность с подсказками,
окружения как желаемое состояние, многоагентность, квитанции, выбор места вывода по метке.
