# Governing documents — живые, управляющие

> **Что это за папка.** Документы, которые **управляют** развитием SIDR прямо сейчас. Они живые:
> меняются вместе с проектом, и расхождение любого из них с репозиторием — дефект, а не история.
>
> Противоположность — [`../design/`](../design/): архив семи импортированных документов, зафиксированных
> как есть при DS-0. Тот архив — **вход**, а не спека; часть его предложений сознательно отменена.

Заведена 2026-08-19 (Этап 3 агентного трека). Причина: дизайновый Master Plan — живой управляющий
документ — лежал внутри папки, объявленной ADR DS-0 «archive of inputs, not the governing spec», и не
входил в её же список семи документов. Категориальная ошибка, которая становится дорогой, когда
появляется второй трек. Он появился.

## Правила папки

1. **Имя файла несёт версию.** `…-v1.2.md`, а не `…​.md`: появление v1.3 иначе проходит незаметно.
2. **Философия и операционная часть не смешиваются.** Принципы прозой живут в дизайновом Master Plan
   §4; проверяемые правила — в матрице. Разные жанры имеют разную судьбу: манифест декоративен,
   таблица с именами тестов — инженерное ограничение (аудит §21, Риск 5).
3. **Содержание не копируется между документами.** Ссылка на раздел, а не пересказ — пересказ есть
   механизм расхождения (прецедент: три конфликта v1↔v1.1 в DS-0).
4. **Матрица проверяется тестом.** `DoctrineMatrixGuardTest`
   (`app/src/test/java/com/sidr/launcher/doctrine/`) читает таблицу и краснеет, если правило заявляет
   тест, которого нет в репозитории.
